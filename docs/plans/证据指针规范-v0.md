# 证据指针规范 v0

生成时间：2026-04-21。
适用范围：EvalShield v1。

## 目的

这份文档定义 `EvidenceRef.pointer` 的稳定指针格式。

`excerpt` 是给人看的。
`pointer` 是给机器与 replay 用的。

## 核心规则

每个非 `trusted` verdict 至少要引用一个可解析 pointer。

`kind` 与 `pointer scheme` 的职责不同：

- `kind` 负责上层语义分类
- `pointer scheme` 负责底层定位机制

两者允许同名，但不是同一层真相。
如果两者冲突，必须在实现中显式报错，不能静默容忍。

## Pointer Schemes

v1 允许的 pointer scheme：

- `file://`
- `jsonpath://`
- `trace://`
- `diff://`
- `prompt://`

## Scheme 定义

### file

用于稳定 file-backed evidence。

示例：

```text
file://cases/curated/leakage-001/review.txt#L10-L24
```

### jsonpath

用于 canonical artifact 内部 JSON 对象引用。

示例：

```text
jsonpath://run.output.structured_findings[2]
```

### trace

用于 run 或 replay trace 的定位。

示例：

```text
trace://tool_calls/7
trace://model_turns/3
```

### diff

用于 PR diff hunk 定位。

示例：

```text
diff://hunk/3
diff://file/src/auth.py#hunk/2
```

### prompt

用于 prompt reference，按 digest 或逻辑槽位定位。

示例：

```text
prompt://system/sha256:abc123
prompt://reviewer/slot:main
```


## Kind 到 Pointer Scheme 的推荐映射

`EvidenceRef.kind` 是语义分类，`pointer` scheme 是定位机制。

| kind | 推荐 pointer scheme | 说明 |
|---|---|---|
| `trace` | `trace://` 或 `jsonpath://` | run / replay trace 定位 |
| `output` | `file://` 或 `jsonpath://` | model output、review text、structured output |
| `metadata` | `jsonpath://` 或 `file://` | benchmark metadata、task metadata |
| `replay` | `trace://`、`jsonpath://` 或 `file://` | replay bundle / replay trace / divergence summary |
| `diff` | `diff://` | PR diff hunk 定位 |
| `prompt` | `prompt://` 或 `file://` | prompt ref 或 prompt digest |
| `workflow` | `trace://` 或 `jsonpath://` | 上游 workflow node / checkpoint / step trace |
| `provenance` | `jsonpath://` 或 `file://` | `RunArtifact.provenance` 或 ingest validation record |

`workflow` 和 `provenance` 不引入新的 URI scheme。v1 不允许 `workflow://` 或 `provenance://`。

## EvidenceRef 最小形态

```text
EvidenceRef
- kind
- pointer
- excerpt
- explanation
```

## Validation 规则

- `pointer` 必须使用允许的 scheme
- 每种 scheme 的语法都必须可解析
- `excerpt` 可以为空
- `explanation` 必须说明这个 pointer 为什么重要
- `kind` 必须合法
- `workflow` kind 必须使用 `trace://` 或 `jsonpath://`
- `provenance` kind 必须使用 `jsonpath://` 或 `file://`
- `kind` 与 `pointer scheme` 若冲突，必须报错

## 明确不做

- 任意 URI scheme
- `workflow://` / `provenance://` pointer scheme
- browser/computer-use pointer 类型
- semantic pointer resolution engine

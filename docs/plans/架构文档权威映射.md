# EvalShield 架构文档权威映射

## 目的

这份文档回答四个问题：

- 每份文档各自负责什么
- 冲突时谁优先
- 哪些信息不能重复写
- 文档应该按什么顺序更新

## 冲突优先级

```text
项目宪法
  > 主文档中的权威规则
  > 契约/规范/矩阵
  > 实施计划 / 启动清单
  > 决策台账 / 术语表
  > 导览文档 / README
```

## 禁止重复写的信息

### 只能在需求文档中定义
- 用户
- 用户场景
- 功能清单
- 非功能要求

### 只能在模块文档中定义
- 模块负责什么
- 模块不负责什么
- 模块复杂度

### 只能在整体架构设计中定义
- 总体结构图
- 数据流
- 核心 tradeoff

### 只能在核心契约文档中定义
- `RunArtifact` 字段列表
- `DetectorFinding` 字段列表
- `TrustVerdict` 字段列表
- digest 规则
- versioning 规则

### 只能在 verdict 策略文档中定义
- `trusted / suspect / invalid` 判定矩阵
- finding 组合优先级
- detector failure 参与 verdict 的规则

### 只能在 replay 文档中定义
- structural / behavioral replay 边界
- replay status 语义
- replay pinning 最小集

### 只能在 evidence 指针文档中定义
- pointer scheme
- pointer 解析规则

### 只能在 exemplar 文档中定义
- `fixtures/pr_review_generic_v0/` 结构
- exemplar 内部文件职责

### 只能在上游评测系统适配边界文档中定义
- upstream eval system adapter 的职责边界
- workflow provenance refs 的适配规则
- 上游 report / trace / raw evidence 缺失时的边界解释

### 只能在 One-Eval 适配分析文档中定义
- One-Eval pipeline 对 EvalShield 的参考价值
- One-Eval artifact 到 RunArtifact 的潜在映射
- One-Eval adapter 的非目标

### 只能在原因码分类文档中定义
- reason code 命名
- family 归属
- 默认严重度
- 是否可作为 primary reason
- 新增 reason code 的流程

### 只能在启动清单中定义
- 第一波实现范围
- 第一波开工顺序
- 第一批测试清单

### 只能在 v1→v2 边界文档中定义
- 哪些能力属于 v1
- 哪些能力属于 v1.1
- 哪些能力只属于 v2
- 双轨版本线（执行层 vs 信任层）

### 只能在架构演进路线图中定义
- 四层信任链（Run Integrity / Output Calibration / Benchmark Validity）
- 信任层各阶段的范围和不做的事
- 与 MIRAGE 论文的关系
- CalibrationReport / BenchmarkValidityReport 等信任层对象

### 只能在 ADR 中定义
- 为什么 v2 不是通用平台
- 为什么分布式能力要长在评测控制面上

# 标准真相包契约 v0

生成时间：2026-04-21。
适用范围：EvalShield v1。

## 目的

这份文档定义所有 PR-review benchmark artifacts 在进入 detector 前必须归一化到的 canonical bundle contract。

外部 benchmark 格式只是输入材料。
EvalShield canonical bundle 才是内部事实真相源。

## 设计规则

- 所有 detector 只能读取 canonical contracts
- 所有 canonical contracts 必须带版本
- 所有持久化 run-like artifacts 必须 digest-addressed
- 外部原始 artifact 格式不能作为长期 truth source
- contract 扩展必须 additive 且 versioned

## 核心对象

EvalShield v1 canonical bundle 由以下对象构成：

- `RunArtifact`
- `DetectorFinding`
- `TrustVerdict`
- `EvidenceRef`
- `ReplayBundle`
- `CaseRecord`

## RunArtifact

`RunArtifact` 是一次 PR-review benchmark run 的权威表示。

### 必需字段

```text
RunArtifact
- schema_version: str
- run_id: str
- created_at: str
- benchmark_name: str
- benchmark_version: str
- task_id: str
- adapter_name: str
- adapter_version: str
- source_artifact_digest: str
- normalized_bundle_digest: str
- environment_fingerprint: str
- input:
  - pr_diff_ref: str
  - repo_context_refs: list[str]
  - task_metadata_ref: str
- execution:
  - model_name: str
  - prompt_refs: list[str]
  - tool_trace_ref: str | null
  - system_metadata_ref: str | null
- output:
  - raw_score: float | int | null
  - review_text_ref: str
  - structured_findings_ref: str | null
  - raw_output_ref: str | null
- provenance:
  - artifact_sources: list[str]
  - ingest_notes: list[str]
  - upstream_runner_name: str | null
  - upstream_runner_version: str | null
  - upstream_workflow_trace_ref: str | null
  - upstream_workflow_trace_digest: str | null
  - upstream_schema_mapping_ref: str | null
  - upstream_metric_plan_ref: str | null
  - upstream_human_overrides_ref: str | null
  - upstream_report_ref: str | null
```

### 规则

- `schema_version` 必须显式，例如：`evalshield.runartifact.v0`
- `source_artifact_digest` 表示 ingest 时使用的原始输入 bundle 的精确 digest
- `normalized_bundle_digest` 表示归一化后 canonical representation 的精确 digest
- `environment_fingerprint` 必须稳定描述 replay 相关环境事实
- `repo_context_refs` 只能存引用，不能内嵌完整仓库快照
- `upstream_*` 字段只记录上游评测系统 provenance，不作为 verdict source
- 上游 report 只能作为 artifact source 或 evidence projection，不能替代 canonical output

### `environment_fingerprint` 最小组成

v1 最少必须包含这些维度：

- runtime / python version
- model identifier
- adapter version
- benchmark version
- prompt digest set
- platform tag

禁止把无边界环境细节全部塞进去，否则 fingerprint 会失去稳定性。

## DetectorFinding

`DetectorFinding` 是 detector 唯一允许输出的契约。

### 必需字段

```text
DetectorFinding
- schema_version: str
- finding_id: str
- family: leakage | exploit | replay | system
- subtype: str
- severity: low | medium | high | critical
- confidence: float
- title: str
- summary: str
- reason_code: str
- evidence_refs: list[EvidenceRef]
- affected_refs: list[str]
- replay_relevance: none | weak | strong
- detector_name: str
- detector_version: str
```

### 规则

- detector 不允许输出 versioned contract 之外的 ad hoc 字段
- 每个 finding 至少包含一个 `EvidenceRef`
- `confidence` 取值必须满足 `0.0 <= x <= 1.0`

## TrustVerdict

`TrustVerdict` 是 machine-authoritative run outcome。

### 必需字段

```text
TrustVerdict
- schema_version: str
- verdict_id: str
- source_run_id: str
- verdict_policy_version: str
- detector_set_version: str
- verdict: trusted | suspect | invalid
- trust_score: float | null
- primary_reasons: list[str]
- findings_ref: str
- summary: str
```

### 规则

- `verdict` 是主要 truth field
- `trust_score` 是可选的辅助信号
- `primary_reasons` 最多 3 个
- 没有明确 `verdict_policy_version` 的 verdict 不能用于长期比较

## EvidenceRef

`EvidenceRef` 指向具体支持证据。

### 必需字段

```text
EvidenceRef
- schema_version: str
- ref_id: str
- kind: trace | output | metadata | replay | diff | prompt | provenance | workflow
- pointer: str
- excerpt: str | null
- explanation: str
```

### 规则

- `pointer` 必须可解析且稳定
- `excerpt` 只是投影展示便利，不是真相源
- 每个非 `trusted` verdict 必须可追溯到至少一个 `EvidenceRef`

## ReplayBundle

`ReplayBundle` 存放 replay attempt 的元数据与引用。

### 必需字段

```text
ReplayBundle
- schema_version: str
- replay_id: str
- replay_contract_version: str
- source_run_id: str
- source_run_digest: str
- replay_mode: structural | behavioral
- replay_status: completed | unavailable | failed
- replay_environment_fingerprint: str | null
- replay_inputs_ref: str
- replay_output_ref: str | null
- replay_trace_ref: str | null
- divergence_summary: str | null
```

### 规则

- v1 必须支持 `structural` replay
- `behavioral` replay 是可选 / 实验性能力
- `replay_status` 必须始终显式，不允许隐式推断

## CaseRecord

`CaseRecord` 是 casebook 原子单位。

### 必需字段

```text
CaseRecord
- schema_version: str
- case_id: str
- case_digest: str
- source_run_id: str
- benchmark_name: str
- category: leakage | exploit | replay
- verdict: trusted | suspect | invalid
- detector_set_version: str
- verdict_policy_version: str
- headline: str
- what_happened: str
- why_it_matters: str
- evidence_refs: list[EvidenceRef]
- replay_refs: list[str]
- tags: list[str]
```

### 规则

- casebook 的 truth source 是结构化 `CaseRecord`，不是 markdown prose
- `case_digest` 在 case 实质内容变化时必须变化
- taxonomy 和 benchmark index 都必须从 `CaseRecord` 派生


## 上游评测系统 provenance 规则

当外部 artifacts 来自 One-Eval 或其他 agentic eval workflow runner 时，adapter 应尽量保留 workflow provenance。

这些字段用于回答：raw score 是如何产生的、是否存在人工介入、benchmark / dataset / metric 是否发生临时漂移。

Upstream provenance 不是 v1 的第四类 trust-failure family。它属于 `system` family 下的 provenance completeness / artifact integrity 风险。

### 规则

- `upstream_runner_name` 和 `upstream_runner_version` 描述上游评测系统
- `upstream_workflow_trace_ref` 指向上游 node / step / checkpoint trace
- `upstream_workflow_trace_digest` 表示 trace 内容 digest
- `upstream_schema_mapping_ref` 指向 dataset / artifact schema mapping 记录
- `upstream_metric_plan_ref` 指向 metric selection / recommendation 记录
- `upstream_human_overrides_ref` 指向人工 interrupt、override、rollback 记录
- `upstream_report_ref` 指向上游 human report，但 report 不是 EvalShield truth source

如果上游系统无法提供这些引用，adapter 必须在 `ingest_notes` 中明确记录缺失项。

### 边界

EvalShield v1 不要求所有上游都提供 workflow trace。
但对于 agentic workflow runner，缺失 trace 或 raw evidence 可以触发 `system` family findings，并使用 `upstream_*` reason codes。

## Digest 策略

### 最低 digest 覆盖范围

- raw source bundle
- canonical bundle
- case record
- upstream workflow trace when provided

### 最低属性要求

- deterministic
- content-addressed
- 算法要在实现文档中说明

v1 可以把具体 digest 算法视为实现细节，但 contract 必须要求稳定 digest 语义。

## Versioning 策略

- 所有 contract objects 都带 `schema_version`
- adapter 带 `adapter_name` 与 `adapter_version`
- detector 输出带 `detector_name` 与 `detector_version`
- verdict 带 `verdict_policy_version` 与 `detector_set_version`

如果这些字段缺失，这个 artifact 就是不完整的，不能当作 canonical truth。

## Ingest 规则

外部 benchmark 格式进入系统的流程是：

```text
external artifact bundle
        ->
adapter parse
        ->
canonical RunArtifact
        ->
detectors / trust engine / replay / casebook
```

在 adapter parse 之后，任何组件都不能依赖外部 raw format 结构。

## Validation 规则

最低验证结果：

- malformed raw bundle -> ingest error
- unsupported adapter version -> ingest error
- 缺失 required canonical fields -> contract error
- digest mismatch -> invalid canonical bundle

## 明确不做

- browser benchmark canonical schema
- multi-family generic artifact schema
- plugin adapter protocol
- generic event bus envelope

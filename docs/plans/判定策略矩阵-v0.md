# 判定策略矩阵 v0

生成时间：2026-04-21。
适用范围：EvalShield v1。

## 目的

这份文档定义 EvalShield 如何把 detector findings 和 replay 状态映射成唯一 machine-authoritative `TrustVerdict`。

v1 使用 rule-based verdict policy。
它不使用 weighted ML scoring 作为主要真相源。

## 核心规则

- `verdict` 是主输出
- `trust_score` 是可选辅助信号
- `primary_reasons` 最多 3 个
- 每个非 `trusted` verdict 都必须引用 evidence-backed reason codes
- detector failure 绝不能静默塌缩为 `trusted`

## 严重度优先级

从强到弱：

1. critical exploit
2. critical leakage
3. high exploit
4. high leakage
5. replay mismatch strong
6. medium exploit
7. medium leakage
8. high system provenance risk
9. replay unavailable
10. medium system provenance risk
11. detector failure
12. low findings / weak anomalies

## 基础判定矩阵

| 条件 | Verdict | Primary reason 规则 |
|---|---|---|
| 无 findings、无 replay 问题、无 detector failures | trusted | none |
| 只有低置信度弱 findings | trusted | none 或 informational only |
| 一条 medium leakage finding | suspect | leakage reason first |
| 一条 high leakage finding | invalid | highest leakage reason first |
| 一条 medium exploit finding | suspect | exploit reason first |
| 一条 high exploit finding | invalid | exploit reason first |
| 任意 family 出现一条 critical finding | invalid | critical reason first |
| replay unavailable，其他都干净 | suspect | `replay_unavailable` |
| upstream report only、无 raw evidence | suspect | `upstream_report_only_no_raw_evidence` |
| agentic workflow trace missing，其他都干净 | trusted 或 suspect，取决于 adapter 风险等级 | `upstream_workflow_trace_missing` conditional |
| upstream human override unaudited | suspect | `upstream_human_override_unaudited` |
| replay mismatch strong，其他都干净 | suspect | replay reason first |
| replay mismatch strong + medium exploit | invalid | exploit before replay |
| replay mismatch strong + high exploit | invalid | exploit first |
| detector failure + no positive findings | suspect | `detector_error` |
| detector failure + 来自其他 detector 的 medium/high finding | suspect 或 invalid，取决于最高 surviving finding | surviving finding first, detector error second |
| detector outputs 冲突，且没有高置信 dominant finding | suspect | `conflict_requires_review` |

## 各 family 说明

### Leakage

- leakage 表示 run 接触了预期 benchmark 边界之外的信息
- high 或 critical leakage 通常判为 `invalid`
- 单独 low-confidence leakage hint 不能直接把 run 打成 invalid

### Exploit

- exploit 表示 run 利用了 benchmark/harness 结构来绕过预期评测
- exploit findings 优先级高于 replay findings
- high exploit 直接判 `invalid`

### System / Upstream Provenance

- `upstream_*` reason codes 属于 system family 下的 provenance completeness 风险
- 它们不代表模型能力失败，而代表 raw score 生成路径不可完全信任
- high upstream evidence gap 通常至少判为 `suspect`
- system provenance findings 通常不应压过 high / critical exploit 或 leakage
- 只有上游 report、缺少 raw artifacts 时，不能判为 `trusted`

### Replay

- replay 是 trust-supporting family，不是 universal truth family
- `replay_unavailable` 本身不直接等于 `invalid`
- replay mismatch 必须有证据支持，不能只是“模型措辞变了”

## Detector Failure Policy

### 规则

Detector failure 绝不能被忽略。

### 结果

- 如果没有正 finding -> `suspect`
- 如果已经有高置信 invalidating findings -> 保持 `invalid`
- `detector_error` 只有在它确实影响 trust interpretation 时，才进入 `primary_reasons`

## Primary Reason Selection

### 规则

最多选三个原因，排序依据：

1. 决定 verdict 的严重度
2. family precedence
3. evidence strength

### 示例

如果一个 run 有：

- high exploit
- medium replay mismatch
- detector failure

那么 primary reasons 应该是：

1. exploit reason
2. replay reason
3. detector error

## Trust Score Policy

v1 可以选择性输出 `trust_score`，但：

- 不能覆盖 `verdict`
- 没有 `verdict_policy_version` 时不能使用
- 它只是展示辅助，不是 policy source

## 边界情况

### Case：clean run，但 replay unavailable

- verdict: `suspect`
- reason: `replay_unavailable`

### Case：low leakage hint，但无强证据

- verdict: `trusted`
- 只有越过证据阈值后才允许升级

### Case：mixed medium leakage + medium exploit

- verdict: `suspect`
- primary reasons 顺序：exploit，再 leakage

### Case：high exploit + replay unavailable

- verdict: `invalid`
- exploit 原因排第一
- replay unavailable 可作为次级说明

### Case：detector conflict

- verdict: `suspect`
- reason: `conflict_requires_review`

### Case：One-Eval style workflow 只有 report，无 raw artifacts

- verdict: `suspect`
- reason: `upstream_report_only_no_raw_evidence`

### Case：上游存在人工 override，但无 diff / audit record

- verdict: `suspect`
- reason: `upstream_human_override_unaudited`

## v1 明确不做

v1 的 verdict policy 不尝试：

- 对 review 质量做 semantic truth evaluation
- 做 cross-model equivalence judgment
- 在 trust 之外给出 agent capability scoring
- 做 probabilistic policy-learning

## Golden Test 要求

这个 policy matrix 中所有被实现的行，都必须至少有一个 golden test 覆盖。

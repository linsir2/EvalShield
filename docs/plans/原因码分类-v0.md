# 原因码分类 v0

生成时间：2026-04-21。
适用范围：EvalShield v1。

## 目的

这份文档统一 reason code 的命名、归属、默认严重度与使用边界。

它不替代 `判定策略矩阵-v0.md`。
它的作用是防止 reason code 在实现期四处漂移。

## 结构

每个 reason code 至少定义：

- code
- family
- 含义
- 默认严重度
- 是否可作为 primary reason

## 命名规则

- 全部使用 snake_case
- 前缀反映 family：
  - `leakage_`
  - `exploit_`
  - `replay_`
  - `detector_`
  - `conflict_`
  - `upstream_` 仅用于 system family 下的上游 provenance 风险
- 不允许同义不同名

## Primary Reason 使用规则

- `detector_error` 只有在它确实影响 trust interpretation 时才能进入 primary reasons
- `replay_unavailable` 可以成为 primary reason，但通常不应压过高危 exploit / leakage
- `upstream_*` 可以成为 primary reason，但它们属于 system family，通常不应压过高危 exploit / leakage
- family 内若已有更高严重度 code，低严重度 code 不应抢 primary slot

## 与 Verdict Policy 的关系

- `reason-code taxonomy` 负责 code 的词汇与语义
- `verdict-policy matrix` 负责 finding 组合如何映射到 verdict

这两者不能互相替代。

## 新增 reason code 的治理流程

新增 reason code 时，顺序必须固定：

1. 先更新 `原因码分类-v0.md`
2. 如果 verdict 行为受影响，再更新 `判定策略矩阵-v0.md`
3. 最后才允许在实现中落该 code

禁止在实现中先发明新 code，再回头补文档。

## 明确不做

- v1 不做层级化 ontology
- v1 不做数百个 reason code
- v1 不做跨 benchmark family 的泛化 taxonomy
- v1 不把上游 workflow 风险扩展成通用 eval 平台 taxonomy
- v1 不把 upstream provenance 提升为第四类 detector family
